## 1. What it is

`QuickDerMethod` (`QuickDerN.jl:437-463`) computes a basis of the derivation space `{(M_a) : Σ_a P[ρ,a] (Γ ×_a M_a) = 0}` for a tensor `Γ` of any valence `n ≥ 2` and any chisel matrix `P` with at least one engaged column, then intersects it with the operator space `Ω` (`_fastder_restrict_to_ops`, shared with the valence-3 oracle). The pipeline is **sketch-restrict / solve / lift / verify**: (1) each axis gets an orthonormal `W_a` (d_a × r_a) — the Q of a Gaussian (`:random`, default) or `I[:,1:r_a]` (`:corner`) — and the cross sketches `S_a = Γ ×_{b≠a} W_b` are built through a shared prefix chain (`_qdn_cross_sketches`, 1092-1110) so only two passes meet `d^n`; (2) the restricted system in `Y_a = M_a W_a` is optionally *whitened* (`whiten = true`, default; thin QR of each unfolded sketch so every diagonal Gram block is `c_a·I`, 1187-1254) and handed to a null solver either as a dense matrix (`_qdn_restricted_matrix`, 1388-1411; `SVDSolver` or `GramSolver` by `QDN_GRAM_MIN_COLS`) or as a `LinearMap` (`_qdn_restricted_map`, 1423-1493; ARPACK if loaded else KrylovKit, 131-132) depending on `QDN_DENSE_BUDGET_BYTES` (2.5 GB host / 6 GB GPU, 91/108); (3) the complement `Z_a = M_a W_a⊥` is recovered per axis by one shared thin QR least-squares solve with a min-norm fallback (1824-1894), and a *consistency filter* keeps only combinations whose lift residual sits below a gap in the residual spectrum (1898-1978); (4) the defining equation is checked as a veto (`_qdn_verify`, 2057-2132; `:random` on `nslices = 4` slices of the largest axis, `:full` below 2e7 entries, `:none`). One retry with `r` bumped 50 % (2336-2345); failure is an `error(...)`.

Public surface: `QuickDerMethod(; restriction=:random, sizes=nothing, solver=:AutoSolver, verify=:random, nslices=4, seed=nothing, device=:cpu, whiten=true)`; `derTrOpsReduced(m, Ω, P, Γ; tol=1e-6, nd=-1, progress=false, return_diagnostics=false)` (2265-2408) returning `(Ω, id_map, ders)` or `(..., report::DerivationReport)`. `nd > 0` is the **`:fixed_nd` policy** (2208-2240): the restricted solve runs with `tol = Inf` and `nd + 2` directions, the filter *reports* residuals instead of vetoing, the Z-law check is skipped, and `certified` is true only when the automatic gap rule lands on exactly `nd` (`_qdn_fixed_verdict`, 1542-1579). Element type follows `eltype(Γ)`: arithmetic runs in `compute_eltype(T)` (Float16 → Float32), the tolerance floor and the null verdict's `data_floor` use the **stored** type (2297-2314, 1698/1728 `store_eltype = store`), and coordinates are rounded back to `T` (2379). `AutoDerMethod` (`AutoDer.jl:37-54`) runs QuickDer when `Ω isa IndTransverseOps`, some axis is engaged, and `prod(dims) ≥ 2000` (`autoder_applicable`, 62-66); any exception from QuickDer is logged at `@info` and the call falls through to `SylverLiningMethod` (85-101). Eleven module-level `Ref`s (77-346) tune budgets, filter constants and expose out-of-band outputs (`QDN_APPLY_COUNT`, `QDN_STAGE_TIMES/BYTES`, `QDN_TRIVIAL_FACTORED`, `QDN_LAST_SOLVE_STATUS`).

## 2. Design assessment

**Sound, and worth saying so explicitly.**

- The four stages are genuinely separated in code, not just in the doc: sketch (`_qdn_cross_sketches`), restricted operator (`_qdn_restricted_matrix` / `_qdn_restricted_map`, both reading the same `coff`/`sdims` bookkeeping so whitening is "one repackaging", 1236-1238), lift, filter, `_qdn_verify`. The verify step is a *veto* (2067-2072, 2087, 2128), and `AutoDer` treats that veto as routing information. That is the right contract for a generically-correct method.
- **The stored type reaches the verdict.** `store::Type` is a positional argument of `_qdn_solve_and_lift` (1631) passed as `store_eltype` to both `solve_nullspace` calls (1698, 1728); `atol` is floored on the stored type (2314) while the arithmetic is promoted (2297-2298); the report carries both (`store_eltype`, `compute_eltype`, `DerivationReport.jl:82-85`) and the Z-law residuals are measured in the compute type on the promoted tensor (`_der_zlaw_residuals`, 286-297). The docstring at 1613-1621 records the measured false certificate that motivated it. This is exactly how a mixed-precision policy should be threaded.
- **Whitening** is exact where the sketch has full rank and *factors out* the trivial space where it does not (`_qdn_whiten_axis` 1187-1205 tests the invariant `‖M_a·un − Q‖`, not a diagonal heuristic; `_qdn_trivial_ders` 1299-1347 re-verifies every kernel column against Γ itself, 1311-1312, rather than trusting the sketch). The unwhitened undercount (16 of 26) is documented and pinned by a test (TestQuickDerN 584-615). Good.
- **Consistency filter as a gap rule** (1936-1976) reusing `gap_verdict` from the null solvers — one rule for "where is zero" across the package — with the Float32 cliff measurements written down (313-346).
- **Failure modes are closed, not papered over**: an empty answer from a non-`:ok` solve raises (1785-1792, `_qdn_empty_result` 2181-2188); `_qdn_fixed_verdict` refuses to certify a caller's count unless the automatic rule agrees (1551); `_qdn_system_rows` pads wide systems so `svd` cannot silently drop null directions (1350-1367).
- **Memory discipline is real**: `_qdn_ttm!` never permutes a host array (642-653), `_qdn_ttm_square!` holds a chain of square mode products to one buffer (692-733), `_qdn_restricted_map` preallocates every scratch (1442-1450) with the single-threaded invariant spelled out (1439-1441), `AZ .-= B` reuse (1886-1890), per-axis QR compression of the residual blocks (1892), and the trivial space is published factored with a byte budget (1322-1345).
- **Device abstraction by array type**: writing the kernel against `AbstractArray` + `similar` so an `MtlArray` flows through with no second implementation (`ext/DletoMetalQuickDer.jl:10-31`) is a good, small design; the ext file is essentially four `to_cpu` wrapper methods (67-70).
- **DerivationReport**: one struct for three routes, `nothing` = "no such number" (DerivationReport.jl:17-23), a keyword constructor that derives the summary from the verdict once (169-222), and `:Auto` reports the route that answered (AutoDer.jl:76-79). Error messages are actionable throughout (223-230, 1786-1791, 2067-2072, 2346-2350).

**Weak.**

- **Policy lives in global `Ref`s, not on the method.** `QDN_GRAM_MIN_COLS`, `QDN_DENSE_BUDGET_BYTES`, `QDN_GPU_DENSE_BUDGET_BYTES`, `QDN_LIFT_GAP_RATIO`, `QDN_LIFT_CEILING`, `QDN_TRIVIAL_MAX_BYTES` (77-346) are per-call policy but are process-global, non-thread-safe, and the tests have to save/restore them in `try/finally` blocks (TestQuickDerN 654-680, 707-727, 754-794, 824-865; TestQuickDerDevice 119-188). The out-of-band outputs (`QDN_APPLY_COUNT`, `QDN_STAGE_*`, `QDN_TRIVIAL_FACTORED`, `QDN_LAST_SOLVE_STATUS`) predate `DerivationReport`, which is now the right home — `stage_times` is already there (DerivationReport.jl:100). The docstrings justify each `Ref` by "the idiom this file already uses" (252, 305), which is circular.
- **Two-way dependency with NullSolvers.jl, patched by include order.** QuickDerN.jl is included before NullSolvers.jl (Dleto.jl:93 vs 99) and names `solve_nullspace`, `GramSolver`, `SVDSolver`, `gap_verdict`, `tol_default`, `NullVerdict`, `SOLVER_REGISTRY`, `wants_square` in bodies only; NullSolvers.jl in turn calls `_qdn_stage!` (NullSolvers.jl:1563, 1590, 1612, 1618). Four separate comments work around this (88-89, 337-339, 1538-1541, 2276-2282) by dropping type annotations and duplicating constants. See F10.
- **`_qdn_solve_and_lift` is 400 lines** (1629-2028) with five `# ----` seams already marked; `derTrOpsReduced` is 144 (2265-2408). The closure `info` (1756-1771) captures `verdict`, `selected`, `next_value`, `solver_used`, which are reassigned in the function (1744-1749, 1690/1720), so they are boxed — harmless here but a lint smell and a reason to split.
- **`device::Symbol` is a two-valued flag whose semantics are Metal's** (Float32-only, 227-230; bandwidth constants measured on an M4 Max, 509-511) while the actual dispatch is `G isa Array` in six places (601, 646, 768, 783, 1021, 2077). See section 5.
- **The dense branch ignores `method.solver`** (1688-1689; documented at 386-390). One keyword meaning "which solver" on one branch and nothing on the other is an API trap.

## 3. Findings (ranked)

### Bugs / correctness risk

**F1. `AutoDer` swallows every exception, including bugs and OOM.** `AutoDer.jl:90-97` catches everything but `InterruptException`, logs at `@info`, and falls back to SylverLining. A `MethodError`, `DimensionMismatch`, `BoundsError` or `OutOfMemoryError` inside QuickDer is therefore invisible, and an OOM on a `d^n` tensor triggers a fallback whose operator is `n·d^{n+1}` — strictly worse. *Fix:* define `struct QuickDerDeclined <: Exception; msg::String; end` in QuickDerN.jl, throw it at the four deliberate decline sites (1786, 2067 `fail`, 2181, 2346), catch only that type in AutoDer, `rethrow()` everything else, and log the decline at `@warn` (a 65-150x slower path is not `@info`). Bonus: put `fallback_reason::Union{Nothing,String}` in the report.

**F2. `kwargs...` accepted and silently dropped.** `derTrOpsReduced(::QuickDerMethod, ...; kwargs...)` (2274) never reads `kwargs`. `derTrOpsReduced(m, Ω, P, Γ; whiten = false)` or `; sizes = ...` is a silent no-op. `AutoDer.jl:87-89, 99-101` forwards the same `kwargs...` to both routes, so a per-call `backend = :metal` meant for SylverLining is dropped when QuickDer answers. FastDer3Valent.jl:620 and QuickSylver.jl:245 share the pattern; only SylverLining consumes a kwarg (`backend`, SylverLining.jl:69). *Fix:* remove `kwargs...` from the QuickDer method (or `isempty(kwargs) || error("QuickDer: unknown keywords $(keys(kwargs)); method options belong on QuickDerMethod")`), and have AutoDer split keywords by destination.

**F3. `NullVerdict` rebuilt positionally with 17 arguments.** `_qdn_fixed_verdict` 1574-1577 constructs `NullVerdict(fx.nullity, :fixed, agrees, v.status, fx.gap, v.gap_ratio, v.floor, fx.floor_binding, ...)` against the struct at NullSolvers.jl:514-531. Inserting or reordering any same-typed field (there are five `Float64`s and four `Int`s in a row) mis-assigns silently. *Fix:* a keyword copy-constructor `NullVerdict(v::NullVerdict; kwargs...)` in NullSolvers.jl (owner of the type); QuickDerN then writes `NullVerdict(v; nullity = fx.nullity, rule = :fixed, certified = agrees, ...)`.

**F4. `QDN_LAST_SOLVE_STATUS` is dead state that can go stale.** Set at 1733 and 2305, read at 2181. Its docstring (254-259) argues the status must be out of band because the caller "only learns the answer is empty one step past the kernel" — but `_qdn_solve_and_lift` now returns `info` with `info.verdict.status` (1768), and `info` is in scope at both `_qdn_empty_result` call sites (2370, 2398). CONTEXT.md:247 records that refactor. A concurrent call or an error between 1733 and 2181 makes the global wrong. *Fix:* `_qdn_empty_result(Ω, T, r, dims, info.verdict.status)`; delete the `Ref`; change TestQuickDerN:715 to assert on the report's `status` (or on the thrown message).

**F5. `:random` verification bound is looser than documented by ~√(d_â/nslices).** `_qdn_verify` 2113 uses `bound = atol · ‖Γ‖ · Σ‖M_a‖` with the *full* `‖Γ‖`, but `E` at 2119-2127 is only the `nslices` slices of the residual tensor. A residual concentrated in the sampled slices is judged against the norm of the whole tensor. The docstring (2048-2050) and design note §4 claim invariance to scale, which holds, but the effective tolerance per slice is `atol · √(d_â/ns)` looser than `:full`. *Fix:* scale the bound by `norm(Gslice)/gnorm` for the sliced term (or document the factor). Low severity — the random check is probabilistic by design — but worth making the number honest.

**F6. Redundant mode products in the lift RHS.** 1839-1847: `Wt = _qdn_ttm(Hs[b], Yv[b,i], b)` and its `_qdn_unfold` are inside the `rho` loop but depend only on `(b, i)`; only the scalar `P[rho, b]` varies. For `CentroidChisel(3)` (`m = 3`) that is 3x the lift's contraction work. *Fix:* hoist `Wt`/its transposed unfolding above the `rho` loop and accumulate `P[rho,b] .* Wu` per row.

**F7. `_qdn_pair_tensor` pays `n(n−1)` full-tensor passes where 2 would do.** Every `(a, b)` pair (1835-1836 inside the `for a in lift` loop) walks its own chain from `G` (1067-1071), so the first `W_c` contraction — the one that meets `d^n` — is recomputed per pair. `_qdn_cross_sketches` already shares a prefix (1092-1110); the lift does not. CONTEXT.md:1023-1024 records "the LIFT is the new wall" on the device. *Fix:* for each lift axis `a`, contract `G` once with the cheapest `W_c` (c ∉ {a}) and derive all `H_{ab}` for `b ≠ c` from it; only `b = c` needs a second full pass.

### API design

**F8. Global `Ref`s as configuration and as output channel.** See section 2. *Fix (incremental):* (i) move `gram_min_cols`, `dense_budget_bytes`, `lift_gap_ratio`, `lift_ceiling`, `trivial_max_bytes` onto `QuickDerMethod` with the current `Ref`s as constructor defaults; (ii) move `apply_count`, `trivial_factored`, `stage_bytes` into `DerivationReport`; (iii) keep `QDN_STAGE_TIMES` as the one benchmarking hook if `GramSolver` must keep writing to it.

**F9. `solver` keyword means different things per branch.** 1688-1689 picks `SVDSolver`/`GramSolver` by size and ignores `method.solver`; 1711-1712 honours it. A user passing `solver = :ArpackSolver` on a d = 60 problem gets an SVD and no message. *Fix:* honour an explicit non-`:AutoSolver` `solver` on both branches (a registered dense-capable solver should be usable), or rename to `free_solver` and document the dense pair as `dense_solver = :auto`.

**F10. Include-order workarounds, one of which rests on a false premise.** (a) `QDN_LIFT_GAP_RATIO = Ref(100.0)` with the comment "that file is `include`d after this one, so the name is not in scope" (337-339) — but `GAP_RATIO` is defined in `Precision.jl:193`, included at `Dleto.jl:64`, *before* QuickDerN.jl. `Ref(GAP_RATIO)` works today. (b) `QDN_DENSE_BUDGET_BYTES` cannot be `DENSE_BUDGET_BYTES/2` for the stated reason (88-89; the constant is at NullSolvers.jl:55) — true. (c) `_qdn_fixed_verdict(v, ...)` unannotated (1538-1541) and `derTrOpsReduced` without a return annotation (2276-2282) — true, because NullVerdict/DerivationReport come later. The root cause is that NullSolvers.jl calls `_qdn_stage!` (NullSolvers.jl:1563-1618). *Fix:* move `QDN_STAGE_TIMES`, `QDN_STAGE_BYTES`, `_QDN_BYTE_MARK`, `_qdn_stage_reset!`, `_qdn_stage!` and the budget `Ref`s into a small `src/solvers/SolverKnobs.jl` included right after Precision.jl; then include NullSolvers.jl and DerivationReport.jl before QuickDerN.jl and restore the annotations. Four comments disappear.

**F11. `_qdn_check_device` runs after the `d^n` promotion copy and duplicates the constructor's check.** 2298 materialises `Array{Tc}(G0)` before 2303 can reject `device = :gpu` with a Float64 tensor; 221-222 repeats the `:cpu|:gpu` validation already done at 457-458. *Fix:* call `_qdn_check_device(method.device, compute_eltype(eltype(Γ)))` first thing after `_qdn_validate`.

**F12. `AutoDerMethod` docstring omits pass-through keywords; `derTrOpsReduced(::AutoDerMethod)` has no docstring.** AutoDer.jl:31-35 lists `restriction, sizes, verify, seed, solver, whiten` but `device` and `nslices` also pass through (51-54). The 68-102 method has only a comment.

### Maintainability

**F13. `_qdn_solve_and_lift` (400 lines, 1629-2028) and `derTrOpsReduced` (144 lines, 2265-2408).** Seams are already commented: whitening (1649-1658), dense/free solve (1668-1731), fixed policy (1735-1750), lift (1815-1896), filter (1898-1980), assembly (1982-2010), trivial merge (2011-2027). *Fix:* `_qdn_restricted_solve(...) -> (vals, vecs, verdict, solver_used, squared)`, `_qdn_lift(...) -> (Zv, Rblocks, scale)`, `_qdn_consistency_filter(...) -> (C, lift_resid)`, `_qdn_assemble_basis(...)`. Each is independently testable, which the whitening test (TestQuickDerN 460-513) already does by hand for the front half.

**F14. Identity `LinearMap` built five times.** QuickDerN.jl:2190, 2405, 2427; FastDer3Valent.jl:650; QuickSylver.jl:299 — same 1-line expression. *Fix:* `_identity_expand_map(Ω)` in Derivations.jl.

**F15. Stale docstring signature.** `_qdn_trivial_ders` docstring (1257) reads `(G, haxs, wh, engaged, eaxes, dims, r, atol)`; the method (1299-1301) is `(G, wh, eaxes, dims, atol)`. Also 141-142 says `GramSolver` adds stages "through the same dictionary" — true, but the dependency it creates is the F10 cycle and should be named as such.

**F16. `_qdn_ttm` docstring contradicts itself.** 558 "NO `permutedims` OF THE INPUT, ever"; 657-658 the device fall-through does `permutedims(G, perm)`. The later paragraph (585-594) explains why; the headline should say "never on the host".

**F17. Bench-only kernel code lives in the solver file.** `_qdn_ttm_square!` (692-733) has no caller in `src/` — its users are `bench/SphereHarness.jl:328,343` and `bench/MemoryProfile.jl:166,177`. Together with `_qdn_ttm`, `_qdn_ttm!`, `_qdn_unfold(!)`, `_qdn_fold`, `_qdn_slice` it is the "one place a backend swap has to touch" the header promises (38-47, 466-467). *Fix:* move the contraction kernel to `src/util/ModeProducts.jl` (no `_qdn_` prefix) so SylverLining's array path and the harness share it and the solver file shrinks by ~350 lines.

**F18. `_QDNAxis{T}` has abstract fields** (`W::AbstractMatrix{T}`, 935-936; acknowledged at 925-929). Adding a second parameter `M<:AbstractMatrix{T}` removes the dynamic dispatch for free and lets `_qdn_axes_device` produce a concretely-typed vector.

**F19. Magic numbers outside Precision.jl.** `QDN_LIFT_CEILING = 32` (346) — no counterpart in Precision.jl; the TODO at 1955-1960 admits `sqrt(eps)` here is a measured constant, not `rank_rtol`. `2e7` full-verify cutoff (2074, 393) unnamed. `0.05` slack and floors `4`/`2` in `_qdn_restriction_sizes` (887, 890) unnamed. `1.5` retry bump (2342) duplicated in the error hint (2071). *Fix:* name them (`QDN_FULL_VERIFY_MAX_ENTRIES`, `QDN_SIZE_SLACK`, `QDN_RETRY_FACTOR`) and move the precision-flavoured ones (`LIFT_CEILING`, the `sqrt(eps)` lift floor) to Precision.jl next to `FLOOR_EPS`/`GAP_RATIO` so the policy document has one home.

**F20. `maxlog = 1` on warnings the report should carry.** 1313, 1334, 1339, 1562, 1927, 2390. DerivationReport.jl:10-11 itself says `maxlog = 1` "silences the second call in a loop over a thousand video blocks". The trivial-space truncation (1339) and the "not trivial derivations — cross sketch lost rank" warning (1313) are per-call facts. *Fix:* `trivial_truncated::Bool`, `trivial_dim::Int` fields on the report.

### Style / naming

**F21.** Two spellings of the same function, `_qd_tolerance` (FastDer3Valent.jl:80, used at QuickDerN.jl:2314) and `qd_tolerance` (Precision.jl:407, named in the docstring at 2205). Pick one (the Precision.jl one) and delete the shim. The repo-level camelCase/snake_case split (`derTrOpsReduced`, `globalDim` vs `get_derivation_method`, `return_diagnostics`) is visible here but originates in Derivations.jl; inside this slice naming is consistent (`_qdn_` snake_case, `_QDNAxis`/`_QDNWhite` CamelCase types).

**F22.** `ext/DletoMetalExt.jl:28,30` includes the two kernel files conditionally on `isfile(...)`. A missing file silently removes GPU support for one kernel with no error; make the includes unconditional.

## 4. Test coverage

**What `test/TestQuickDerN.jl` covers (1158 lines):** random dense valence 3/4/5 nullity `n−1` in Float64 and Float32 (141-202); diagonal valence-4 nullity `3d` (210-242); valence-3 oracle-vs-SylverLining span (249-272); unscrambled sparse sphere valence 3/4, `:random` gets 13 (285-334); scrambled sphere valence 3/4 through `run_stratify` (349-376); disengaged axis `P = [1 1 0]` (383-407); `CentroidChisel(3)` (417-441); the whitening Gram identity, spectrum bound, `M_a·un == Q`, fold/unfold round trip (460-513); whitened == unwhitened span on six shapes incl. 20×20×10×3 (521-568); degenerate mode counted `2 + 2d` (584-615); forced matrix-free branch with `:KrylovSolver`, apply counter (647-682); empty-from-unconverged raises and `:Auto` recovers (700-728); factored trivial space and byte cap (739-796); lift gap rule neutrality in Float32/Float64 on d = 24, 32 spheres and the nullity-13 raw sphere (818-867); `return_diagnostics` on 2 cases × 2 types × 2 methods with residuals recomputed independently (886-1029); `:fixed_nd` — five back on nullity three, ordering, certification, residual separation, `nd == nullity` certifies, constrained Ω warns (1046-1158). This is strong, oracle-anchored coverage of the numerics.

**`test/TestQuickDerDevice.jl`:** cost model (`_qdn_slab_is_cheap`, `_qdn_mode_cost`, host order stays `1:N`), shapes of sketches/pair tensors (73-105) run everywhere; the GPU half (111-189) — CPU vs GPU span for Float32 and Float16, no host-width copies, slab vs permute agreement — runs only when `using Metal` succeeds (32-37).

**`test/TestAutoDer.jl`:** routing predicate on small/big/no-engaged (27-36); `:Auto` == SylverLining nullity at valence 3/4 (38-48); `stratify` default recovers the valence-4 sphere (50-57).

**Missing or weak:**

- **Float16 on the CPU is untested.** The only Float16 case (TestQuickDerDevice 124) is inside `if DEVICE_TESTS`. CONTEXT.md:206-222 describes the Float16 false-certificate fix, but no test in this slice pins `certified == false`/`undecidable > 0` on a Float16 near-degenerate tensor through `:QuickDer`, nor that `eltype(ders) === Float16` on the CPU.
- **Valence 5 with an actual restriction.** The one valence-5 case is (4,3,3,3,2) (147), where every axis saturates (`r == d`, no sketch, no lift, no whitening). Add e.g. (8,7,6,5,4) so `r < d` on the large axes.
- **Empty derivation algebra (legitimate `k == 0`)** — 1802 and the `:ok` branch of `_qdn_empty_result` (2189-2192) are never exercised; every test's Ω carries the identity so scalars always exist. A chisel with `dim ker P = 0` (e.g. `P = I(3)` on a random 3-tensor) covers it.
- **`:corner` has no positive test** — only test 4's `corner_ok` (322-328), whose `catch → true` makes any exception, including a `MethodError` regression, pass. Assert `@test_throws ErrorException` there, and add a dense-generic case where `:corner` must match `:random`.
- **Error paths untested:** `_qdn_check_sizes` (904-912), the 1.5x retry and the final "every restricted solution failed" error (2336-2350), `device = :gpu` without a backend (223-226) and with Float64 (227-230) — the last two would run on every machine.
- **`_qdn_ttm!` with `α/β`, `_qdn_ttm_square!`, `_qdn_unfold!`, wide-system padding (`_qdn_system_rows`) — no direct tests** in `test/`.
- **AutoDer:** the non-`IndTransverseOps` routing (`autoder_applicable` line 63) and the `min_entries` keyword are untested; the fallback-on-error path is tested only via TestQuickDerN:717.
- **Stale scaffolding:** the header (5-13), `QUICKDER_AVAILABLE` (101), `OLD_V3_SYMBOL` (107-112), `SPHERE_VALENCE_KW` (123-128) and every `else @test_skip` arm (171, 199, 239, 330-331, 373, 405, 439, 462, 523, 586, 649, 702, 741, 820, 888, 1048) describe a pre-landing world. Delete them; the `@test_skip`s inflate the skipped count in CI output.
- **Three copies of `der_residual`** (TestQuickDerN 29-42, TestQuickDerDevice 39-46, TestAutoDer 12-18) plus `basis_matrix`/`subspace_residual`/`principal_angle` — move to a `test/TestUtils.jl`. The suite also `include`s `bench/SphereHarness.jl` (121; TestAutoDer 51), so tests depend on the bench tree.

## 5. Extensibility

- **A new null solver for the restricted system:** easy on the matrix-free branch — any registered `Symbol` passes through `solve_nullspace` (1711-1729) and `wants_square`/`SOLVER_REGISTRY` handle the rest. On the dense branch it is impossible without editing 1688-1689 (F9).
- **A new device (CUDA, oneAPI):** hard. Requirements today: (a) a second ext that defines the same four global hooks `to_gpu/to_cpu/GPU_AVAILABLE/GPU_SYNC` (NullSolvers.jl:1082-1108) — two backends cannot coexist; (b) `_qdn_check_device`'s Float32-only rule and Apple-specific messages (227-230); (c) the cost model constants (509-511) measured on one M4 Max and applied to any non-`Array`; (d) six `G isa Array` tests (601, 646, 768, 783, 1021, 2077) as the de-facto device predicate. *Suggestion:* a `Device` trait (`CPU()`, `Metal()`, `CUDA()`) on `QuickDerMethod` with `supported_eltypes(dev)`, `stream_bw(dev)`, `permute_bw(dev)`, `launch_s(dev)`, and `on_device(x, dev)`; the ext defines the trait's methods. The `AbstractArray + similar` kernel design (38-47) already does the hard part.
- **A new chisel type:** free. The kernel consumes `Matrix{Tc}(P)` and `engaged(P)` (2317-2318); `CentroidChisel` and `AdjointChisel` already run (TestQuickDerN 417-441, 464-467) with no chisel-specific code anywhere in QuickDerN.jl.
- **A new restriction (structured sketch, sparse `W`):** moderate. `_qdn_axis` (939-949) and the `ident::Bool` flag on `_QDNAxis` are the only switch; a third kind means editing `_qdn_modeW`, `_qdn_modeWp`, `_qdn_assemble`, `_qdn_mode_cost` (963-994, 1043-1046). An `AbstractSketch` with `apply(W, G, a)`, `apply_perp`, `assemble` would localise it.
- **A new contraction backend (Strided/TensorOperations/Finch):** the seam is four functions (`_qdn_ttm!`, `_qdn_unfold(!)`, `_qdn_fold`, `_qdn_slice`), not one as the header says (39-41), but they are adjacent and small (F17 would make them a module).
- **A new derivation method under `:Auto`:** `AutoDerMethod` hard-codes exactly two fields, `quick::QuickDerMethod` and `fallback::SylverLiningMethod` (38-40). A `Vector{DerivationMethod}` tried in order with a per-method `applicable(m, Ω, P, Γ)` predicate would admit `QuickSylverMethod` (adjoint chisels) without a rewrite.
